# 0010 — Хранение закрытого ключа устройства в T1

**Статус:** Accepted
**Дата:** 2026-09-04

## Контекст

TLS identity устройства должна сохраняться между перезапусками, а закрытый
ключ нельзя хранить открытым файлом в `ProgramData`. Целевая архитектура
предпочитает non-exportable CNG machine key, но прямое использование такого
ключа как signing backend для rustls заметно расширяет Windows FFI и блокирует
сетевой milestone до отдельной реализации криптографического provider.

## Рассмотренные варианты

1. **Persisted non-exportable CNG key** — лучший Windows security boundary,
   но требует собственного rustls/rcgen signing adapter поверх NCrypt и
   существенно увеличивает объём критичного unsafe-кода T1.
2. **PKCS#8, защищённый Windows DPAPI в machine scope** — ключ расшифровывается
   только в памяти LocalSystem-процесса и на диске не существует в открытом
   виде. Он остаётся технически exportable после расшифровки и поэтому слабее
   варианта CNG.
3. **Открытый PKCS#8 в `ProgramData` с ACL** — проще, но прямо запрещён T1 spec
   и делает утечку файла утечкой identity.

## Решение

Для T1 используется вариант 2: ECDSA PKCS#8 шифруется через
`CryptProtectData` с флагом `CRYPTPROTECT_LOCAL_MACHINE` и только после этого
записывается в каталог состояния ClassOS. Сертификат является публичным и
может храниться отдельно без шифрования. Расшифрованный буфер и экземпляр
identity зануляют память после использования, насколько это допускают API
используемых библиотек.

Перед production security review вариант 1 должен быть повторно рассмотрен.
TPM-backed CNG key остаётся будущим усилением и не блокирует T1.

## Последствия

- Копирование зашифрованного файла на другой компьютер не переносит identity.
- Любой процесс с достаточными локальными machine-привилегиями потенциально
  может вызвать DPAPI и получить ключ; это явно слабее non-exportable CNG.
- Потеря DPAPI blob означает новую identity и требует повторного enrollment.
- Реальное поведение DPAPI и ACL проверяется только на Windows; host unit-тесты
  покрывают формат и криптографическую identity, но не заменяют runtime-тест.
