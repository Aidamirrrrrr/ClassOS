# 0011 — Параметризованный захват кадра в локальном IPC T3

**Статус:** Accepted
**Дата:** 2026-09-04

## Контекст

T2 передаёт через локальный IPC уже закодированный единичный JPEG-кадр. В T3
Teacher Console задаёт режим потока, целевой FPS и максимальную ширину кадра.
Если Session Host всегда будет передавать исходный full-resolution JPEG, режим
thumbnail станет расходовать сеть и CPU как selected mode, что противоречит
спецификации T3 и local-first работе класса.

## Рассмотренные варианты

1. Масштабировать JPEG в Service — требует декодировать и заново кодировать
   кадр в привилегированном процессе и добавляет лишнюю копию.
2. Передавать сырой BGRA-кадр через Named Pipe — резко увеличивает объём IPC и
   делает Service владельцем desktop-данных без необходимости.
3. Передавать Session Host параметры JPEG-кадра в существующем
   `CaptureRequest` — захват, масштабирование и кодирование остаются в
   интерактивной сессии, а Service только маршрутизирует эфемерные байты.

## Решение

Выбран вариант 3. В `CaptureRequest` добавляются необязательные
`max_width` и `jpeg_quality`. Нулевые значения означают совместимые настройки
T2: исходная ширина и качество по умолчанию. Session Host ограничивает оба
значения безопасными пределами, масштабирует raw BGRA до кодирования и не
сохраняет кадр на диск.

## Последствия

- Сетевой `StreamSubscribe` остаётся единственным источником schedule;
  Service не доверяет его значениям напрямую и применяет ограничение T3.
- Изменение остаётся обратно совместимым для T2: старый запрос с нулями даёт
  единичный JPEG исходного размера.
- Никакие raw desktop bytes не пересекают границу Service / Session Host.
