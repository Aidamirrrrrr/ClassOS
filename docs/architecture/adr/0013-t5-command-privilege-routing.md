# 0013 — Маршрутизация classroom-команд через границу привилегий

**Статус:** Accepted
**Дата:** 2026-09-04

## Контекст

T5 добавляет команды блокировки экрана, сообщения, запуска приложения, открытия
URL, перезагрузки и выключения. Они приходят по аутентифицированному сетевому
каналу в LocalSystem Service, но часть действий должна выполняться только в
пользовательской сессии. Нельзя превращать Session Host в канал выполнения
произвольных привилегированных команд.

## Рассмотренные варианты

1. Выполнять все команды в Service — не подходит для overlay, UI, URL и запуска
   пользовательского приложения.
2. Передавать все команды в Session Host — не подходит для restart/shutdown и
   нарушает границу привилегий.
3. Service валидирует сетевую команду, хранит idempotency-кэш и маршрутизирует
   только разрешённые user-session действия через типизированный IPC; системные
   power-действия выполняет сам Service.

## Решение

Выбран вариант 3. Service остаётся единственным владельцем дедлайна,
idempotency-кэша, audit-записи и результата команды. Session Host получает
только строго типизированные действия: Lock/Unlock overlay, ShowMessage,
LaunchApplication из allowlist и OpenUrl с безопасной схемой. Restart и Shutdown
не передаются в пользовательскую сессию.

## Последствия

- В network и local IPC используются отдельные, но эквивалентные command
  сообщения; Service не доверяет сообщению из Session Host как источнику новых
  привилегий.
- Произвольный путь, командная строка и PowerShell не являются вариантами
  протокола.
- Повторный `command_id` возвращает закешированный результат, не запускает
  действие второй раз.
- При потере Session Host его user-session команда завершается предсказуемой
  ошибкой; power-команды не зависят от IPC.
