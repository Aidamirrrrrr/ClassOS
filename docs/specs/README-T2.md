# ClassOS T2 — одиночный снимок экрана

Статус по `docs/specs/BACKLOG.md`: **код завершён и проходит автоматические
проверки; DXGI и реальный capture ни разу не выполнялись на Windows/GPU.**

## Уже реализовано

- crate `screen-capture` с разделёнными контрактами `ScreenCapture` и
  `FrameEncoder`;
- `MockCapture` с обнаружением нескольких дисплеев и выбором primary;
- JPEG-кодирование RGB-кадра без сохранения на диск;
- protobuf-сообщения `CaptureRequest`, `Frame`, `CaptureError` для local IPC;
- protobuf-сообщения `ScreenshotRequest`, `ScreenFrame` для T1-канала;
- encode/decode и JPEG round-trip unit-тесты.

## Реализовано дополнительно

- DXGI Desktop Duplication за `ScreenCapture` в Session Host;
- `CaptureRequest` через T0 IPC и `ScreenFrame` через Service;
- кнопка снимка и отображение JPEG в Teacher Console.

## Исправлено после сквозной ревизии

Основным считался **первый перечисленный выход DXGI**, а не основной монитор
Windows. Порядок перечисления с расположением мониторов не связан, поэтому на
машине с двумя экранами преподаватель мог смотреть на соседний монитор,
считая, что видит рабочий. Теперь основным считается монитор с началом
рабочего стола в (0, 0), и он всегда получает `display_id = 0` — именно этот
идентификатор приходит в запросе без явного выбора дисплея.

Отдельно: Teacher Console молча игнорировала `CaptureError`, приходящий в
потоке кадров, — сбой захвата выглядел как застывшая картинка (§13.5).

## Осталось

Обязательная приёмка на Intel/AMD/NVIDIA, 1080p/4K и двух мониторах — не
выполнялась.

Кадры по умолчанию живут только в памяти: capture → encode → отправка →
discard. Debug-dump на диск в T2 не добавляется.
