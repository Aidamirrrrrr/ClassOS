# ClassOS — чеклист runtime-приёмки T0–T8

**Файл:** `docs/specs/RUNTIME_ACCEPTANCE.md`
**Назначение:** прогон на реальном оборудовании, который снимает статус
`Runtime validation: not started` в [BACKLOG.md](BACKLOG.md).

Этот документ существует потому, что весь код T0–T8 проходит автоматические
проверки и **ни разу не исполнялся на настоящей Windows**. Прогон по памяти
здесь не годится: пропущенный пункт выглядит точно так же, как пройденный.

Правило заполнения: пункт отмечается пройденным только по наблюдаемому
результату. «Должно работать по коду» — это `не проверено`, а не `пройдено`.
Найденный дефект записывается в столбец «Наблюдение» и заводится задачей, а
не «исправляется по ходу» — иначе прогон превращается в отладку и перестаёт
быть приёмкой.

---

## 1. Что нужно до начала

### Стенды

Один стенд закрыть весь набор не может:

| Стенд | Что закрывает | Чего не закрывает |
| --- | --- | --- |
| Windows-VPS без видеоадаптера | T0, T1, T5 (кроме overlay), T6, T7, T8 | **T2, T3, T4** — DXGI Desktop Duplication требует настоящего display adapter |
| Физический ПК с GPU | всё | — |
| Две машины в одной LAN | T1 discovery, T3 grid, многопользовательские сценарии | — |

Минимум для полного прогона: **один физический ПК с GPU** плюс вторая машина
(любая) для сетевых сценариев. VPS полезен как постоянный стенд для T0/T6/T7/T8.

### Учётные записи

```text
[ ] Учётная запись администратора (установка, break-glass)
[ ] Учётная запись standard-user "student" — под ней проверяется T6
[ ] Вторая учётная запись standard-user "student2" — для Acceptance Test D и pipe ACL
```

Проверка T6 под администратором ничего не доказывает: политика рассчитана на
ученический аккаунт, и именно он должен упираться в запрет.

### Сборка

```powershell
cargo build --workspace --release --target x86_64-pc-windows-msvc
```

```text
[ ] Собраны classos-service.exe, classos-session.exe, classos-updater.exe
[ ] Сборка выполнена с CLASSOS_PUBLISHER_KEY_HEX, если проверяется обновление
```

Без ключа издателя агент компилируется, но **отказывается обновляться** — для
блока T8 это означает заведомо непройденные пункты.

## 2. Порядок

Порядок не произвольный: каждый блок опирается на предыдущий, и провал
раннего блока обесценивает результаты поздних.

```text
T0 → T1 → T2 → T3 → T4 → [CHECKPOINT #1] → T5 → T6 → T7 → T8 → chaos
```

Если блок провален — прогон останавливается на нём. Продолжать по следующим
блокам можно только осознанно, отметив это в журнале.

## 4. T1 — сеть и обнаружение

Нужны две машины в одной LAN.

| # | Действие | Ожидается | Статус | Наблюдение |
| --- | --- | --- | --- | --- |
| 1 | Запустить Teacher Console, «Найти устройства» | Устройство появляется само, без повторных нажатий | | |

| 6 | Отключить устройство от сети | Консоль показывает потерю связи, а не «зависает» | | |
| 7 | Подключить обратно | Соединение восстанавливается | | |
| 8 | **Закрыть и снова открыть Teacher Console** | Устройства остаются зарегистрированными, команды проходят без повторной регистрации | | |

перезапуск консоли терял credential безвозвратно, а сменившийся адрес делал
устройство видимым, но недостижимым. Ни то, ни другое не наблюдалось
работающим.

### 12.4 Security checklist (§10)

```text
[ ] signed installer                 — требует Authenticode-сертификата

```

Первые два пункта закрываются покупкой сертификата и `scripts/release.ps1`;
до этого T8 не готов к первому платному филиалу независимо от остального.

Пункт про enrollment закрывается не прогоном, а кодом: решение принято
(ADR-0018), протокольная часть не написана. Отмечать его пройденным по
результатам приёмки нельзя — проверять там пока нечего.

## 13. Chaos-набор (T8 §11)

Проводится в конце, на собранной системе, во время смоделированного урока.

| # | Сценарий | Ожидается | Статус | Наблюдение |
| --- | --- | --- | --- | --- |
| 1 | Падение Session Host | Supervisor поднимает, урок продолжается | | |
| 2 | Отключение преподавателя | Устройства не остаются в подвешенном состоянии | | |
| 3 | Пропажа интернета | Урок продолжается по lease | | |
| 4 | Выход ученика из системы | Корректная очистка | | |
| 5 | Перезагрузка Windows | Всё поднимается само | | |
| 6 | **Sleep / wake** | Соединение восстанавливается без вмешательства | | |
| 7 | Переключение пользователя | Session Host следует за активной сессией | | |
| 8 | Обрыв и восстановление сети | Reconnect без ручных действий | | |
